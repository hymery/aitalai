## 2. Что строим

ИИ-собеседник на базе DeepSeek API с двумя режимами:

1. **«Сценарий»** — ролевой диалог на башкирском с персонажем-маскотом в рамках
   ситуации (чаепитие у бабушки, знакомство, путешествие). Пользователь пишет
   свободным текстом, персонаж отвечает в роли, мягко исправляет ошибки.
   Сценарии привязаны к курсам и открываются по мере прохождения.
2. **«Устаз»** — свободный чат с ИИ-учителем: объясняет грамматику, разбирает
   слова, отвечает на вопросы, учитывая прогресс пользователя (какие юниты
   пройдены, какой словарь известен).

Ключевые принципы:

- **Это игровая фича, а не «чат с нейронкой»**: собеседник — живой маскот с
  эмоциями (спрайты), облачками, анимациями, очками и экраном итогов.
- **Модель НЕ должна выдумывать башкирский**: в контекст DeepSeek подкладываем
  словарь пройденных юнитов и разговорные фразы; системный промпт ограничивает
  словарный запас. DeepSeek знает башкирский слабо — grounding обязателен.
- **Фича не должна ломать приложение**, если ИИ недоступен: без ключа API
  бэкенд отдаёт `enabled: false`, фронт показывает экран «скоро».

### 3.3. Эндпоинты (все под `Depends(get_current_user)`, префикс `/ai`)

| Метод и путь | Ответ | Логика |
|---|---|---|
| `GET /ai/status` | `{enabled: bool, daily_left: int}` | флаг + остаток дневного лимита |
| `GET /ai/scenarios` | `[{id, title_ru, character, unit_id, unlocked, completed_today}]` | `unlocked` по прогрессу юнита |
| `POST /ai/sessions` body `{mode, scenario_id?}` | `{session_id, greeting: AiReply}` | создаёт сессию; для scenario — greeting персонажа из конфига; для tutor — приветствие Устаза. Если у юзера есть `active` сессия того же mode+scenario — вернуть её вместо новой |
| `GET /ai/sessions/{id}` | `{session, messages: [...]}` | восстановление истории (только владелец) |
| `POST /ai/sessions/{id}/messages` body `{text}` | `AiReply` | основной ход: см. 3.4 |
| `POST /ai/sessions/{id}/finish` | `{points, report: {messages_count, corrections_count, new_words}}` | начисление очков, см. 3.5 |

`AiReply` (schemas.py):

```python
class AiReply(BaseModel):
    reply_ba: str
    reply_ru: str
    emotion: Literal["idle","success","fail","special","thinking"] = "idle"
    corrections: list[Correction] = []   # {wrong, correct, explanation_ru}
    new_words: list[WordPair] = []       # {ba, ru}
    hint: str | None = None
```

### 3.4. Логика сообщения (POST .../messages)

1. Проверки: сессия существует, принадлежит юзеру, `status=="active"`,
   дневной лимит (считать AiMessage роли user юзера за текущие сутки) —
   при превышении 429 с понятным `detail`.
2. Сохранить сообщение юзера.
3. Собрать контекст:
   - системный промпт (см. 3.6): роль, режим, персонаж, правила;
   - словарный запас: `unit_vocabulary` всех юнитов, где
     `user_unit_progress.circle_1_done` (до ~200 слов, формат `ba — ru`);
   - последние `AI_MAX_HISTORY` сообщений сессии в формате chat completions.
4. Вызвать DeepSeek (JSON mode). Распарсить ответ в `AiReply`; при
   невалидном JSON — один retry с уточняющей инструкцией, затем фолбэк
   `{reply_ba: "Ағай, мин аңламаҙым. Тағы бер тапҡыр әйтегеҙ.", ...}`.
5. Сохранить assistant-сообщение (`text=reply_ba`, `meta` = весь AiReply).
6. Вернуть `AiReply`.

### 3.5. Очки

- `finish`: если юзер написал ≥3 сообщений и `points_awarded == 0`:
  +30 очков (`user.points += 30`, как существующие начисления), записать в
  `points_awarded`. Повторный finish той же сессии очки не дублирует.
- Рейтинги подхватят очки автоматически (они считаются по `users.points`).

следующий вопрос. Правило «не выдумывай башкирские формы» — то же.

### 4.3. Модалка чата — сердце фичи (сделать «на высоте»)

Новая `#modal-dialog` по образцу `#modal-lesson` (`div.duo-modal`), но
полноэкранная на мобиле и с собственной компоновкой:

```
┌──────────────────────────────────────────┐
│ ✕   [мини-маскот 48px] Өләсәй   «Чаепитие» │  шапка: .duo-modal__header
├──────────────────────────────────────────┤
│        (фон scene-waves, --blue-50)        │

│   ●●●  пузыри персонажа — слева,        │
│        белые облачка (.cloud) с хвостиком│
│        + строка перевода (курсив, muted, │
│        скрыта → раскрывается по тапу     │
│        «показать перевод»)               │
│                          пузыри юзера ●● │
│                       справа, --blue-500 │

├──────────────────────────────────────────┤
│ [чипы-подсказки: «Сәләм», «Рәхмит»...]    │
│ [поле ввода + кнопка башк. клавиатуры] [➤]│
└──────────────────────────────────────────┘
```

Требования к поведению и анимациям (ВСЁ обязательно):

1. **Мини-маскот в шапке** живой: пока ждём ответ — спрайт `thinking`,
   по ответу — эмоция из `emotion` поля (маппинг через `spriteUrl`), через
   1.2–1.6 сек возврат в `idle`. Используй механику `characters.js`
   (`setState`-подход, не дублируй логику).
2. **Индикатор печати**: пузырь персонажа с тремя прыгающими точками
   (CSS-анимация, цвет `--ink-500`), появляется сразу после отправки.
3. **Появление пузырей**: keyframes `bubble-in` — снизу вверх на 12px +
   scale 0.92→1 + fade, `var(--t-base)` c `cubic-bezier(.2,.9,.3,1.2)`
   (лёгкий «поп», в духе игры). Пузырь юзера — сразу, без задержки.
4. **Эффект печатания** для ответа персонажа: текст reply_ba набирается
   посимвольно (15–25 мс/символ), автоскролл ленты; кнопка-скип по тапу на
   пузырь. После набора — плавно показать перевод-строку и (если есть)
   карточки исправлений и «новых слов» (золотая и зелёная подложки,
   каскад 80ms).
5. **Перевод по тапу**: под каждым пузырем персонажа строка-перевод свёрнута;
   тап по пузырю — раскрытие (max-height transition, `var(--t-base)`).
6. **Чипы-подсказки** над полем ввода: 2–4 готовые фразы (первый ход — из
   конфига сценария, далее — из `hint` ответа модели; если hint пуст — скрыть).
7. **Поле ввода**: `.input` + кнопка отправки `.btn-primary` (иконка-стрелка),
   Enter = отправить, кнопка экранной башкирской клавиатуры (переиспользуй
   bashkir-keyboard.js — вставка в позицию курсора). Лимит 300 символов.
8. **Завершение**: кнопка «Завершить диалог» в шапке (справа) → bottom-sheet
   подтверждения (по образцу `#lesson-exit-sheet`) → `POST /finish` →
   **экран итогов** поверх ленты: большой маскот (success/special),
   начисленные очки с анимацией счётчика и вылетом `i-honey` (как после
   уроков), статистика (сообщений, исправлений, новых слов), кнопки
   «Ещё раз» и «К диалогам».
9. **Пустые/ошибочные состояния**: сеть упала — тост «Сервер временно
   недоступен» + пузырь-заглушка персонажа; лимит 429 — карточка
   «На сегодня диалоги закончились, возвращайся завтра» с маскотом
   `bear_sleepy`.
10. **Восстановление**: при открытии активной сессии подгрузить историю
    (`GET /ai/sessions/{id}`) и отрендерить без анимаций.
11. **Доступность**: лента — `role="log" aria-live="polite"`, фокус-ловушка
    в модалке, Esc закрывает (с подтверждением, если диалог активен),
    `prefers-reduced-motion` — отключить печатание и bubble-анимации.

### 4.4. Ноды-диалоги на карте курса

- В рендере карты (`course-content`, функции отрисовки нод в app.js /
  course-data.js) после босс-ноды каждого юнита добавить ноду типа «диалог»:

## 6. Жёсткие ограничения

- НЕ менять существующие эндпоинты, таблицы, экраны и механику уроков;
  только добавления. Существующие тесты должны остаться зелёными.
- НЕ трогать `bot/` (Telegram/MAX) — отдельная задача.
- НЕ добавлять голос/STT в диалоги (TTS-кнопку у пузырей НЕ делать).
- НЕ хранить ключ DeepSeek на фронте; только backend.
- Без новых npm-зависимостей на фронте; из Python — только `httpx`.
- Весь новый UI-текст — на русском, названия/реплики персонажей — на
  башкирском, как принято в проекте.

## 7. Критерии приёмки

1. Таб «Диалоги» с иконкой spark между «Курс» и «Сообщество»; роутинг
   по `#dialogs` работает, прямая ссылка открывается.
2. Закрытый сценарий показывает замок; после прохождения 1 этапа юнита —
   открывается и на хабе, и нодой на карте.
3. Диалог: отправка → точки печати → typewriter-ответ с эмоцией маскота →
   перевод по тапу; ошибки юзера разбираются в золотых карточках.
4. `finish` начисляет +30 один раз; очки видны в топбаре и рейтинге.
5. История диалога восстанавливается после перезагрузки страницы.
6. Без `DEEPSEEK_API_KEY` приложение работает как раньше, таб показывает
   «скоро».
7. `python -m compileall -q backend`, все unittest, `node --check`,
   `npm run build` — зелёные.
